- **API version:** `authentik.weebo.io/v1alpha1`
- **Scope:** Namespaced
- **Short names:** none
- **Guide:** [First application walkthrough](/docs/guides/first-application#2-create-the-application-oauth2-provider)

Mirrors `authentik_application` + its `protocol_provider`. Namespaced —
owned by whichever team/namespace created it, governed by
`AuthentikNamespacePolicy`.

## Example

```yaml
apiVersion: authentik.weebo.io/v1alpha1
kind: AuthentikApplication
metadata:
  name: my-application
  namespace: team-a
spec:
  instanceRef:
    name: main
  name: Harbor
  slug: harbor
  provider:
    kind: oauth2
    oauth2:
      authorizationFlow: default-provider-authorization-implicit-consent
      invalidationFlow: default-provider-invalidation-flow
      allowedRedirectUris:
        - matchingMode: strict
          url: https://harbor.example.com/c/oidc/callback
```

## Spec fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| [`instanceRef`](#spec.instanceRef) | `object` | yes |  | The `AuthentikInstance` or `AuthentikLocalInstance` this application lives on. |
| `metaIcon` | `string` | no |  |  |
| `name` | `string` | yes |  |  |
| [`provider`](#spec.provider) | `object` | yes |  | `oauth2`/`proxy` are implemented in v1 (both are in real use in the Terraform module being replaced — `longhorn.tf` uses `proxy`). `saml`/`ldap` are schema-only stubs: accepted by the schema so a future addition isn't a breaking change, but rejected by the reconciler with an explicit error, never silently ignored. See `.prompt/plan.md` decision 2.<br /><br />Deliberately **not** a Rust sum type (`enum Foo { Oauth2(..), Proxy(..) }`) even though that's what it conceptually is: kube-core's CRD schema generation cannot merge an internally-tagged enum whose variants carry different literal discriminator values — each variant's `kind` property gets a different `enum: [...]` schema and `CustomResourceExt::crd()` panics ("Property 'kind' ... must be identical"). This flat-struct-plus-discriminator shape is the standard kube.rs workaround; "exactly one of `oauth2`/`proxy` set, matching `kind`" is validated by the reconciler, not the schema. |
| [`secretTargets`](#spec.secretTargets) | `object[]` | no |  | Where this application's oauth2 credentials are written. When empty (the default), they go to one target named after this CR, in its namespace, on the `AuthentikInstance`'s `secretStore.backend`. When non-empty, they are **fanned out** to every listed target; Kubernetes and Vault targets may be mixed. A target stays in this CR's namespace, and a Vault `path` under `<pathPrefix>/<namespace>/` unless the instance's `pathGrants` open it to this namespace. Only meaningful for `provider.kind: oauth2` — proxy providers carry no client secret, so this is ignored for them. |
| `slug` | `string` | yes |  | The application's slug: its URL in Authentik and its identity there (`status.authentikId`). Changing it renames the application in place; its access policies follow. |

### `spec.instanceRef` [#spec.instanceRef]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `kind` | `string` | no |  | The kind of instance a reference designates.<br /><br />Values: `"Instance"`, `"LocalInstance"` |

| `namespace` | `string` | no |  | Namespace of a `LocalInstance`. Defaults to this object's own; required on a cluster-scoped object. Another namespace's local instance must share itself with this one (its `sharedWith`). |

- namespace only applies to kind LocalInstance — `!has(self.namespace) || !has(self.kind) || self.kind == 'LocalInstance'`

### `spec.provider.oauth2` [#spec.provider.oauth2]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `accessTokenValidity` | `string` | no |  | How long an access token stays valid, in Authentik's duration spelling: `"minutes=30"`, `"hours=1"`, `"days=1"`, or several joined by `;`. It governs the ID token minted alongside it too, which is what makes it worth setting: a consumer that replays an ID token as a credential -- `docker login` against a registry that validates OIDC bearers, for one -- lives exactly this long before it has to get another.<br /><br />Omitted leaves the value alone: the field is not sent, so a provider tuned by hand keeps its setting and a new one takes Authentik's default. That is deliberate, and it is what keeps adopting an existing provider free of surprises. |

| `grantTypes` | `string[]` | no | `[]` |  |
| `invalidationFlow` | `string` | yes |  |  |
| `issuerUrl` | `string` | no |  | The issuer consumers trust, written as `AUTHENTIK_URL` and in `status.issuerUrl`, when it is not the one Authentik computes, `<instance url>/application/o/<slug>/` — Authentik served under another public URL than the instance's `url`. Unset: computed.<br /><br />Constraints: `pattern: ^https?://` |
| `propertyMappings` | `string[]` | no | `[]` |  |
| `signingKey` | `string` | no | `"authentik Self-signed Certificate"` | Name of an existing Authentik certificate key pair used to sign tokens. Resolved by name at reconcile time (never created by this operator).
